configuration, tests, and CI. Opened the ESPN NFL website in the in-app browser.
The browser blocked direct API navigation (`ERR_BLOCKED_BY_CLIENT`); direct HTTPS

  checksums, fetch timestamp, method IDs, deduplicated query names, and coverage
  against explicit full URLs in README and sport references. Placeholder names
  and sport/league names are normalized. Relative table paths and prose may
  describe additional routes, so `in_sport_docs: false` is a conservative review

  ingestion to every historical competition.

  HTTP status and top-level response keys rather than full athlete/news bodies.

## Service and repository fixes

- **Injury snapshot data loss:** flatten team-grouped responses; normalize object
  injury types; validate before deletion; replace snapshots atomically; clear
  stale injuries for a valid empty list; preserve old data for malformed input.
- **Repeated transaction inserts:** upsert ID-less Site transactions using their
  natural fields. A database identity constraint and migration now consolidate historical duplicates, retaining the most recently updated row.
- **Lost athlete statistics:** retain Common v3 `categories` data instead of
  storing an empty object; require an explicit season when the response omits
  its year instead of silently saving year zero. Season statistics are filtered to the requested year and career totals are excluded; the full upstream response remains in `raw_data`.
- **Terminal errors retried:** All terminal 4xx errors now bypass retries. Only transport failures and server failures retry.
- **Anonymous production ingestion:** production ingestion POSTs now require an
  authenticated staff user. Local/test defaults and public reads are unchanged.
- **NHL production configuration:** require explicit secret key and allowed
  hosts. Added the missing README referenced by its package metadata.
- **Broken coverage CI:** removed `-p no:cov`, which disabled the plugin while
  passing coverage options; run tests once with coverage and propagate failures.
- Fixed reported Ruff issues across both services.

## Validation and remaining limitations

Follow-up fixes completed: per-record savepoints for teams, events, news, and
transactions; locked injury snapshot replacements; database-enforced transaction
identities; a tested duplicate-consolidation migration; shared CLI/Celery league
configuration; and the missing MIT license. NHL transport now closes reliably,
avoids retrying permanent failures, rejects malformed team snapshots, accepts
plain/localized standings abbreviations, and uses each standing's actual date.

Final local test results: **200 ESPN tests passed, one PostgreSQL-only test skipped; 23 NHL tests and two catalog-parser tests passed**. Django system and migration checks and Ruff passed.

Coverage now exceeds the enforced **80%** gate for both services (approximately
**85.65% ESPN / 97.63% NHL** locally). Added migration, rollback, CLI, worker retry,
broker-failure, HTTP-routing, NHL ingestion, and read-only API tests. A PostgreSQL
concurrent-refresh test runs in CI; SQLite intentionally skips it. CI selects
PostgreSQL through `TEST_DATABASE_URL` instead of silently using SQLite, and a
separate job builds the Docker image and runs the suite against PostgreSQL.

and manually integrated its event-schema contribution with attribution, valid

The practical discovery boundary remains: the catalog covers both Core WADLs;
private/fantasy APIs and every undocumented ESPN host cannot be exhaustively
proven from them. Live probes now span NFL, NBA, MLB, NHL, Premier League, and
college football. A route appearing in WADL does not guarantee public support.
These are evidence limits, not unresolved implementation tasks.

No production database was selected or overwritten. The deployment migration
`0003_transaction_identity` consolidates duplicate transaction identities,
keeping the latest row; back up a deployed database before applying it because
a reverse migration cannot reconstruct discarded duplicates. Test databases are
disposable. The refreshed league snapshot includes historical competitions, so
the shared scheduler list deliberately remains a curated subset.

Local Docker Desktop could not start, and direct NHL API requests returned 403
in this environment. NHL behavior is covered with mocked HTTP and database tests;
The [Docker/PostgreSQL integration job](https://github.com/pseudo-r/Public-ESPN-API/actions/runs/36724313481/job/109917122400) passed on GitHub, including migration and concurrent refresh coverage.
Python 3.14 emits a third-party pytest-asyncio deprecation warning; CI uses the
supported Python 3.12/3.13 matrix.
